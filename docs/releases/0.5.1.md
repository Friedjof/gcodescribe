## Bug fixes: saved printer connection settings

Fixes a successful green connection test followed by “printer not configured” in the application header, especially after configuring a fresh Flatpak installation.

The connection test and printer controller now use the same effective settings, including the saved URL, API key and SSL verification option. Saving or resetting these settings updates the existing printer client without restarting the app or resetting the serial worker. A connection change uses its own status cache, so an old connection result cannot hide the new configuration.

The header refreshes after saving or resetting settings. Explicitly empty credentials are respected instead of silently falling back to environment variables.

## Direct USB / serial printers

Saved serial activation, device path, baudrate and default backend now reach the printer manager and worker. Enabling serial also selects it when the previously active OctoPrint connection was unconfigured and no explicit backend selection was saved.

Idle connection changes take effect without restarting the application. Changes made during an active or paused job are deferred until the job ends, so saving a new port or disabling serial cannot disconnect that plot. Editing only OctoPrint settings leaves an existing serial worker untouched. The serial port is always released on application shutdown.

## Installation

Update to the attached `GCodeScribe-v0.5.1.flatpak`, or install the Debian package:

```sh
sudo apt install ./gcodescribe_0.5.1_amd64.deb
```

Existing saved connection settings are retained. Both fixes are covered by regression tests and the printer/settings integration test suite, including simulated serial printers. Physical USB hardware has not been tested.
