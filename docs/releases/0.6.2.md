# GCodeScribe v0.6.2

This patch corrects the desktop loading screen and prevents stale interfaces after Flatpak updates. It also provides English documentation and screenshots.

## Desktop startup and updates

- The loading screen uses the same current GCodeScribe icon as the application, replacing the old hardcoded illustration. It supports system light/dark appearance and reduced motion.
- Desktop startup uses a frontend-specific URL while keeping the local origin and MCP endpoint unchanged. This bypasses entry pages cached by earlier installations without deleting user preferences.
- HTML entry points are served with `Cache-Control: no-store`. Flatpak normalises installed file timestamps; equal-length HTML from different builds could otherwise share an ETag and incorrectly return HTTP 304. Versioned JavaScript, CSS and other assets retain normal conditional caching.
- Projects, profiles, fonts, saved printers and local interface preferences are retained.

## English documentation

- The README, screenshot gallery, hardware instructions and technical documentation are in English.
- All eleven app screenshots use English UI labels and English demo artwork.
- The editable example font is named Workshop. The v2 hardware downloads remain available.

## Updating

Fully quit GCodeScribe before installing the new Flatpak and launch it again afterwards. Reinstalling while the previous app process is still running does not replace that process.

Use the installation location where the app is already installed. Check it with:

```sh
flatpak list --app --columns=application,version,installation
```

For an existing system installation:

```sh
flatpak install --system ./GCodeScribe-v0.6.2.flatpak
```

For an existing user installation:

```sh
flatpak install --user ./GCodeScribe-v0.6.2.flatpak
```

Do not delete the application data directory to refresh the interface. The startup correction preserves it.
